การติดตั้งและใช้งาน ChartDB (Offline Mode)

ChartDB คือเครื่องมือสำหรับออกแบบฐานข้อมูล (Database Design tool) ที่ทำงานบนหน้าเว็บ มีจุดเด่นด้านความสวยงาม ลื่นไหล และสามารถเปลี่ยนข้อมูลดิบ (DDL Script) ให้กลายเป็นแผนภาพ ER Diagram (Entity-Relationship Diagram) ได้ในไม่กี่วินาทีด้วยระบบ AI และ Query Parser

การติดตั้ง ChartDB บน Server ของเราเองผ่าน Docker จะช่วยให้ทีมงานสามารถใช้งานได้แบบ Offline 100% ข้อมูลโครงสร้างฐานข้อมูลที่เป็นความลับขององค์กรจะไม่ถูกส่งออกไปยังภายนอก เพื่อความปลอดภัยสูงสุด

ส่วนที่ 1: การติดตั้ง ChartDB

ในคู่มือนี้เราจะตั้งค่าให้ ChartDB ทำงานบนโดเมน chartdb.vecskill.ovec (หรือ chartdb.vecskill.ovec ตามที่คุณเลือกใช้) และเชื่อมต่อผ่าน Network กลาง app_net เพื่อให้สามารถทำ Reverse Proxy ร่วมกับ Caddy หรือ Nginx Proxy Manager ได้

ขั้นตอนที่ 1.1: ติดตั้งผ่าน Docker Command Line

หากคุณต้องการรันอย่างรวดเร็วด้วยคำสั่งเดียวบน Terminal:

sudo docker run -d --name chartdb --network app_net -p 8008:80 --restart always ghcr.io/chartdb/chartdb:latest

ขั้นตอนที่ 1.2: ติดตั้งผ่าน Portainer Stack (วิธีแนะนำ)

ไปที่ Portainer > Stacks > + Add stack ตั้งชื่อว่า chartdb-stack แล้ววางโค้ด Docker Compose นี้ใน Web editor:


services:
  chartdb:
    image: ghcr.io/chartdb/chartdb:latest
    container_name: chartdb
    ports:
      - "8008:80"  # สามารถเปลี่ยน 8008 เป็นพอร์ตอื่นที่ต้องการได้ เช่น 9000:80
    #environment:
    #  - OPENAI_API_KEY=your_openai_api_key_here # ใส่ Key ถ้าต้องการใช้ฟีเจอร์ AI ช่วยเขียน/ปรับแต่ง SQL
    restart: always
    networks:
      - app_net

networks:
  app_net:
    external: true

คลิกที่ปุ่ม Deploy the stack แล้วรอระบบดึง Image มาทำงานสักครู่

ส่วนที่ 2: การทำ Reverse Proxy และ HTTPS

หลังจากติดตั้งสำเร็จ ให้คุณเลือกทำตามโปรแกรม Proxy ที่คุณเลือกใช้ในบทก่อนหน้านี้เพื่อชี้โดเมนเข้าหากล่อง ChartDB

เพิ่มคอนฟิกใน `Caddyfile`

เปิดไฟล์ /srv/caddy/Caddyfile แล้วเพิ่มบรรทัดคอนฟิกนี้ลงไป:

chartdb.vecskill.ovec {
    reverse_proxy chartdb:80
}

บันทึกไฟล์แล้ว Caddy จะโหลดคอนฟิกใหม่และสร้าง HTTPS ให้โดเมนนี้โดยอัตโนมัติ

เพิ่ม Proxy Host ใน Web UI

  1. ไปที่หน้าเว็บ NPM (Port 81) > Add Proxy Host
  2. Domain Names: chartdb.vecskill.ovec
  3. Forward Hostname: chartdb
  4. Forward Port: 80
  5. ในแท็บ SSL เลือกขอใบรับรอง (Request new...) และติ๊ก Force SSL แล้วบันทึก

ส่วนที่ 3: วิธีการใช้งาน ChartDB เบื้องต้นแบบ Offline

เปิดเว็บเบราว์เซอร์แล้วเข้าสู่ระบบผ่านโดเมนที่คุณตั้งค่าไว้ เช่น https://chartdb.vecskill.ovec

  1. สร้าง Diagram ใหม่จากศูนย์ (Blank Canvas):
    คุณสามารถคลิกปุ่ม "+" หรือสร้าง Table ใหม่ ลากเส้นความสัมพันธ์ระหว่าง Primary Key (PK) และ Foreign Key (FK) ได้อย่างอิสระผ่านระบบ Drag & Drop
  2. การ Import ข้อมูลจากฐานข้อมูลเดิม (Reverse Engineering):
    นี่คือฟีเจอร์เด่น หากคุณมีโครงสร้างฐานข้อมูลเดิมอยู่แล้ว (เช่น MySQL, PostgreSQL, SQL Server) ให้รันคำสั่งดึง DDL Script (คำสั่ง `CREATE TABLE`) จากฐานข้อมูลเดิมของคุณ จากนั้นคลิกเมนู Import / Export บน ChartDB แล้ววางโค้ดสคริปต์ SQL ลงไป ระบบจะวาดหน้าตาโครงสร้างเป็นตารางเชื่อมโยงกันให้เองโดยอัตโนมัติ
  3. การทำงานแบบ Offline เต็มรูปแบบ (Local Storage):
    เนื่องจากเราใช้งานแบบ Offline ข้อมูลโครงสร้างแผนภาพทั้งหมดจะถูกบันทึกไว้ใน Local Storage ของเว็บเบราว์เซอร์เครื่องที่คุณใช้งาน ไม่ได้ส่งไปยังระบบ Cloud ของผู้พัฒนา เพื่อป้องกันไฟล์สูญหายเมื่อล้างเบราว์เซอร์ แนะนำให้ทำตามข้อถัดไป
  4. การเซฟและสำรองข้อมูล (Export Project):
    เมื่อออกแบบเสร็จแล้ว ทุกครั้งควรคลิกปุ่ม Export เพื่อดาวน์โหลดไฟล์เก็บไว้ในเครื่องของคุณ:
    • Export as JSON (.json): เพื่อเก็บไฟล์โปรเจกต์ไว้ กลับมา Import เพื่อแก้ไขโครงสร้างและขยับย้ายตารางต่อได้ในวันหลัง
    • Export as Image (.png / .svg): สำหรับนำรูปภาพแผนภาพโครงสร้างไปใส่ในเอกสารคู่มือโปรเจกต์ (Documentation)
    • Export as SQL DDL: แปลงแผนภาพที่เรานั่งวาดทั้งหมด ออกมาเป็นโค้ดสคริปต์ SQL เพื่อนำไปสั่งรันสร้างฐานข้อมูลจริงใน Server

คู่มือไวยากรณ์ DBML เบื้องต้น (DBML Syntax Cheat Sheet)

DBML (Database Markup Language) เป็นภาษาที่เข้าใจง่ายสำหรับออกแบบโครงสร้างฐานข้อมูล (Database Schema) เพื่อนำไปแสดงผลเป็น ER Diagram ในเครื่องมืออย่าง ChartDB หรือ dbdiagram.io

องค์ประกอบ / รูปแบบ คำอธิบายโครงสร้าง (Syntax) ตัวอย่างการใช้งาน (Example)
1. การสร้างตาราง
(Table Definition) 		ใช้คำว่า Table ตามด้วยชื่อตาราง และเปิด-ปิดด้วยปีกกา { } 
Table users {
  id int
  username varchar
}
2. คีย์หลัก
(Primary Key) 		ใส่ข้อความ [pk] หรือ [primary key] ไว้ท้ายชื่อฟิลด์ข้อมูล 
Table products {
  id int [pk]
  name varchar
}
3. ข้อจำกัดข้อมูล
(Constraints) 		ระบุเงื่อนไขในวงเล็บเหลี่ยม [ ] เช่น [not null], [unique], [increment] 
Table users {
  email varchar [unique, not null]
  id int [pk, increment]
}
4. ค่าเริ่มต้น
(Default Value) 		ใช้คำสั่ง [default: value] สำหรับฟังก์ชันระบบให้ใช้สัญลักษณ์ backtick (`) 
Table orders {
  status varchar [default: 'pending']
  created_at timestamp [default: `now()`]
5. ความสัมพันธ์
(One-to-Many:
หนึ่ง ไป หลาย) 		ใช้สัญลักษณ์ > หมายถึง ฝั่งซ้ายมีได้หลายรายการ (Many) ลิงก์ไปหาฝั่งขวาที่มีรายการเดียว (One) 
Table posts {
  id int [pk]
  user_id int [ref: > users.id]
}
6. ความสัมพันธ์แบบเขียนแยก
(Ref outside Table) 		เขียนกำหนดความสัมพันธ์แยกออกมาด้านนอกตาราง โดยใช้คำสำคัญ Ref: 
Ref: posts.user_id > users.id
7. คำอธิบายเพิ่มเติม
(Notes / Comments) 		ใช้คำสั่ง [note: "ข้อความ"] ภายในฟิลด์ หรือใช้คอมเมนต์โค้ดด้วย // (ไม่ควรเขียนไว้บรรทัดแรกสุดใน ChartDB) 
Table products {
  status int [note: "1=Active, 0=Inactive"]
}
// นี่คือคอมเมนต์อธิบายโค้ด
💡 คำแนะนำสำหรับ ChartDB: หลีกเลี่ยงการใส่คอมเมนต์ // ไว้ที่บรรทัดแรกสุดของไฟล์ เพื่อป้องกันการเกิด Syntax Error ในตัวแปลงรหัส (Parser) ของระบบ

ตัวอย่างหน้าจอเครื่องมือระบบ ChartDB

หน้าจอเริ่มต้นใช้งาน เพื่อเลือกประเภทและระบบฐานข้อมูลที่ต้องการออกแบบ (ตัวอย่างเลือก MySQL)

หน้าต่างการนำเข้าข้อมูล (Import your Database) ให้คลิกเลือกวิธีเป็นแบบ DBML

วางสคริปต์ DBML ของระบบร้านค้าลงในช่องขวามือ ระบบจะตรวจสอบความถูกต้องของ Syntax และขึ้นแถบสีเขียวเตือนเมื่อผ่าน

ระบบแสดงแผนภาพความสัมพันธ์ ER Diagram ฝั่งขวา และตัวช่วยจัดการสคริปต์ฝั่งซ้ายหลังจากกดปุ่ม Import

แถบเมนูฝั่งซ้ายสลับเป็นหน้าต่าง Tables สำหรับคลิกดูโครงสร้าง ฟิลด์ข้อมูล คีย์หลัก และข้อจำกัด (Constraints) ของแต่ละตาราง

ขั้นตอนการส่งออกชุดคำสั่งเพื่อนำไปสร้างจริงใน Database โดยเลือก Actions -> Export SQL -> MySQL

หน้าต่าง Pop-up แสดงโค้ดสคริปต์ MySQL DDL (CREATE TABLE) ที่แปลงจาก DBML สำเร็จ สามารถคัดลอกไปรันบนระบบฐานข้อมูลได้ทันที
