การทำระบบ CI/CD ด้วย GitLab (Node.js + Docker + SSH Deploy)

คู่มือนี้จะพาคุณสร้าง Pipeline เพื่อ Automate กระบวนการพัฒนาซอฟต์แวร์ ตั้งแต่การทดสอบ (Test), การสร้าง Docker Image (Build), และการนำขึ้น Server จริง (Deploy) โดยอัตโนมัติเมื่อมีการ Push โค้ด

ภาพรวมการทำงาน: GitLab Runner Build Image -> Push to Registry -> SSH to Production -> Pull & Run

ส่วนที่ 1: เตรียมความพร้อม (Infrastructure)

1.1 ตั้งค่า Insecure Registry (สำคัญมาก)

เนื่องจากเราใช้ Registry ภายใน (registry.vecskill.ovec) แบบไม่มี SSL Certificate ที่ถูกต้อง เราต้องบอกให้ Docker ทั้งฝั่ง Runner และฝั่ง Production ยอมรับมัน

แก้ไขไฟล์ /etc/docker/daemon.json (ถ้าไม่มีให้สร้างใหม่):

{
  "insecure-registries" : ["registry.vecskill.ovec", "registry-ui.vecskill.ovec"]
}

จากนั้นรีสตาร์ท Docker:

sudo systemctl restart docker

1.2 สร้าง SSH Key สำหรับ Deploy

เราต้องสร้างกุญแจเพื่อให้ GitLab Runner สามารถ SSH เข้าไปวางไฟล์และรันคำสั่งที่เครื่อง Production ได้โดยไม่ต้องใช้รหัสผ่าน

  1. ที่เครื่อง DevOps (หรือเครื่องของคุณ): สร้าง Key 
    ssh-keygen -t ed25519
    (กด Enter ไปเรื่อยๆ ไม่ต้องใส่ Passphrase)
  2. ดู Public Key (ตัวแม่กุญแจ): 
    cat ~/.ssh/id_ed25519.pub
    ผลลัพธ์: ssh-ed25519 AAAAC3NzaC... root@devops
  3. นำ Public Key ไปใส่ที่เครื่อง Production:
    • SSH เข้าไปที่เครื่อง Production
    • แก้ไขไฟล์ ~/.ssh/authorized_keys
    • วาง Public Key ที่ได้ต่อท้ายบรรทัดเดิม
  4. ดู Private Key (ตัวลูกกุญแจ - เก็บเป็นความลับ): 
    cat ~/.ssh/id_ed25519
    ผลลัพธ์: -----BEGIN OPENSSH PRIVATE KEY----- ตัวคีย์-----END OPENSSH PRIVATE KEY----- (คัดลอกเก็บไว้ทั้งหมดเพื่อใช้ในขั้นตอนต่อไป)

ส่วนที่ 2: ตั้งค่า GitLab Project

2.1 สร้าง Project และตั้งค่า Variable

  1. สร้าง Blank Project ชื่อ vecskill
  2. ไปที่ Settings -> CI/CD -> Variables
  3. กด Add variable
    • Type: Variable
    • Visibility: Variable
    • Key: SSH_PRIVATE_KEY
    • Value: (วาง Private Key -----BEGIN OPENSSH PRIVATE KEY----- ... ที่คัดลอกมาทั้งหมด)
    • Flags: เลือก Protect variable

2.2 สร้าง Runner

  1. ไปที่ Settings -> CI/CD -> Runners -> New project runner
  2. Tags: ใส่คำว่า docker (ต้องตรงกับในไฟล์ .gitlab-ci.yml)
  3. นำ Token ไป Register ที่เครื่อง Runner (ดูวิธีในการติดตั้ง Gitlab Runner)

ส่วนที่ 3: เตรียมไฟล์โปรเจกต์ (Coding)

3.1 Dockerfile

สร้างไฟล์ Dockerfile สำหรับ Node.js App:

FROM node:22
WORKDIR /app
# Copy package.json ก่อนเพื่อใช้ Cache
COPY package*.json ./
RUN npm install
COPY . .

EXPOSE 80 
CMD ["node", "index.js"]

3.3 .gitlab-ci.yml (Pipeline Config)

ไฟล์กำหนดขั้นตอนการทำงานของ CI/CD

stages:
  - test
  - build
  - deploy

variables:
  # แก้ไข IP เครื่อง Production ให้ถูกต้อง
  PRODUCTION_IP: "192.168.100.102"
  PRODUCTION_USER: "root"
  IMAGE_NAME: "registry.vecskill.ovec/my-image:latest"

# --- TEST STAGE ---
test_job:
  stage: test
  image: node:22
  tags:
    - docker
  script:
    - npm install
    # - npm test (ถ้ามี)

# --- BUILD STAGE ---
build:
  stage: build
  image: docker:24
  services:
    - docker:24-dind
  tags:
    - docker
  variables:
    DOCKER_TLS_CERTDIR: ""
  script:
    - docker info
    - docker build -t $IMAGE_NAME .
    - docker push $IMAGE_NAME
  only:
    - main

# --- DEPLOY STAGE ---
deploy_to_production:
  stage: deploy
  image: alpine:latest
  tags:
    - docker
  before_script:
    # ติดตั้ง SSH Client และเตรียม Key
    - apk add --no-cache openssh-client
    - mkdir -p ~/.ssh
    - echo "$SSH_PRIVATE_KEY" | tr -d '\r' > ~/.ssh/id_ed25519
    - chmod 600 ~/.ssh/id_ed25519
    - ssh-keyscan -H $PRODUCTION_IP >> ~/.ssh/known_hosts
  script:
    # 1. ส่งไฟล์ docker-compose ไปที่ Server
    - scp -i ~/.ssh/id_ed25519 -r ./docker-compose.yaml $PRODUCTION_USER@$PRODUCTION_IP:/opt/docker-compose.yaml
    
    # 2. Remote SSH ไปสั่ง Pull และ Up
    - |
      ssh -i ~/.ssh/id_ed25519 $PRODUCTION_USER@$PRODUCTION_IP "
        cd /opt &&
        docker compose pull &&
        docker compose --profile production up -d --remove-orphans
      "
  only:
    - main

ส่วนที่ 4: เริ่มต้นใช้งาน (Execution)

4.1 Push Code ขึ้น GitLab

# ในโฟลเดอร์โปรเจกต์
git init
git remote add origin https://gitlab.vecskill.ovec/root/vecskill.git
git add .
git commit -m "Setup CI/CD"
git branch -M main
git push -uf origin main

4.2 ตรวจสอบผลลัพธ์

  1. ไปที่ GitLab Project -> Build -> Pipelines
  2. คุณควรจะเห็นสถานะเป็น Passed ทั้ง 3 ขั้นตอน (Test, Build, Deploy)
  3. ไปที่เครื่อง Production ลองตรวจสอบ Container: 
    docker ps
    (ควรเห็น Container myservice, mysql2, phpmyadmin2 ทำงานอยู่)
